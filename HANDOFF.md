## Rules that still apply
- The PLAY strip layout and the arranger layouts are ilana's own designs: polish, never undo. UI reviews score against Vital and Serum 2; no unused space is the top priority.
- **Old presets must not change.** Check with `ilanaFingerprint` before and after, then `python tools/compare_fingerprints.py before.csv after.csv`. `build/fingerprints-m7.5.csv` is the current Windows baseline (256 presets; the first 250 match `build/fingerprints-m7.2.csv`); on Linux, `tests/fingerprints-linux.csv` (committed; `tools/verify.sh` compares against it) (with a row per filter model; Live Body and Live Wah always differ run to run) (`build/fingerprints-v1.2.csv` is v1.2's). New presets are appended at the end of the list. Against v1.2, 26 reverb presets differ at the tool's 48 kHz only, because the reverb now gets the real sample rate. At 44.1 kHz they are unchanged. Two more (Through-Zero Growl, Shift Bass) differ only because voice random state carries over between presets within the run. The release polish changed fingerprints on purpose, each explained in ROADMAP: debug 1 (38: continuous knobs; a patch load resets tails and modulators, so fingerprints no longer depend on the preset before), debug 2 (21: voice state cleared on load), debug 5 (14 strings: tuning fix). The Linux baseline is updated; fingerprints are identical run to run.
- **Parameter IDs and choice indices are never renumbered.** New choices, destinations and sources are appended.
  - Mod destinations: the 115 legacy parameter destinations are fixed at 96..210; OSC 4â€“6 start at 211; newer parameters are appended after `Destination::Count` (`paramDestinationFor`), in list order (M4's 89, then M5/M6's 52). `maxDestinations` is 1024 (989 used: M7.3's pickup and M7.5's input parameters came after M7.2's BODY; review 7 appended 534 more so every ring-drawing knob takes a source).

- **Randomness:** new features get their own random generators (as `lfoPoolRandom` and the FM noise operator's `fmNoiseRandom` do), so existing presets' random sequences don't shift. Physical string banks have explicit seeds for the same reason.
- **Per-block parameter reads** use a `ParamRef` member (resolved once), not a string built each block (CPU pass).
- **New features default to the old behaviour** and skip their code while unused (feedback type, noise, key scaling, PD chain), so old presets render bit-identically.
- **Sounds are fitted to a reference before they count as done** (ROADMAP, "When a milestone is done").
